Step 1 — The traditional API call returns unstructured text

A plain LLM API call — same parameters in, raw text out, every time

User Input

Summarise my open tasks for today

🤖LLM API
model:"claude"
Temperature:0.1
messages:[{ role: 'user', content: … }]
Text Output

Here are your open tasks for today: finish the Q2 report, review the PRs from Sarah, and prepare the client demo slides. You also have a 3pm standup.

⚠️

Same call shape every time — but the output is unstructured plain text. Every response has a different format. You cannot reliably parse it, store it, or act on it programmatically.

Step 2 · Combine system prompt, workspace, and user message

user_prompt = build_user_prompt(system_prompt, message, existing_tasks)

Rules, live tasks, and the question are merged into one prompt.

🤖

Step 3 · Provider returns a validated AiDecision

decision = ai_provider.get_decision(user_prompt) # → AiDecision

The provider returns JSON. Your app checks it against the AiDecision schema.

🔧AiDecisionJSON Schema
assistant_message:stringrequired
action:enumrequired
create_task · list_tasks · update_task · delete_task:object

Only the payload for the chosen action is filled — other branches stay empty.

→ AiDecision (validated)
{
  "assistant_message": "Added: Review PRs before Friday.",
  "action": "create_task",
  "create_task": {
    "title": "Review PRs before Friday",
    "status": "todo",
    "priority": 1
  }
}
⚡

Step 4 · Execute the action against the database

result = execute_ai_action(db, decision) # routes by decision.action

decision.action picks the handler — here create_task inserts a new row.

→ Task row saved
