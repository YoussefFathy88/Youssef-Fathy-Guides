Tools & Function Calling

Understand what tools are, why agents need them, and how the tool-use loop works end to end

The LLM is the brain -- it reasons, plans, and decides. But a brain with no hands can only talk. Tools are the hands: they let the agent take real actions in the world -- read a live price, write to a database, send an email, run code. This session explains what tools are, what forms they take, and exactly how the agent uses them.

👤YOUYou define tools and send the user message

POST /v1/messages { tools: [{ name: 'get_weather', description: '...', input_schema: {...} }], messages: [{ role: 'user', content: 'What is the weather in Cairo?' }] }

Your API call includes a tools array alongside the user message. Each tool has a name, a description the model reads to decide when to call it, and an input_schema defining what arguments it must provide.

The description is what the model uses to decide when to call a tool

Vague tool description vs precise tool description

Toggle between the two sides to compare.

Vague description -- model guesses when to use it

  • name: 'get_data'
  • description: 'Gets data from the system'
  • Model does not know what data, from where, or when
  • May call it for unrelated queries or skip it when needed
  • Produces inconsistent, unreliable behavior
VS

Precise description -- model knows exactly when to use it

  • name: 'get_order_status'
  • description: 'Look up the current status of a specific customer order by order ID. Use this when the user asks about a specific order, shipment, or delivery. Returns: status, estimated delivery date, and tracking number.'
  • Tells the model: what it does, when to use it, what it returns
  • Produces consistent, reliable tool calls every time

What we covered

ToolAny callable function you expose to the model -- can wrap a REST API, database query, code executor, or internal service
tool_use blockThe structured JSON the model returns when it wants to call a tool -- contains the tool name and the arguments your code should use
tool_result blockThe message you send back containing the output of the function you executed
input_schemaA JSON Schema definition specifying what arguments the model must provide when calling a tool
Parallel tool callsWhen the model requests multiple independent tools in one response so your application can run them simultaneously
