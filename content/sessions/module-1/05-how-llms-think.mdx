{/* SECTION 1 - GOAL */}

<SessionSection id="goal" label="Goal">

## Understand what the model actually does differently when it "thinks" -- and whether it is really reasoning

You have seen that LLMs predict one token at a time. This session answers a question every developer eventually asks: when I turn on "thinking mode", what is mechanically different inside the model? Is it actually reasoning, or is it just generating more tokens? And when should you pay for it?

</SessionSection>


{/* SECTION 2 - BIG PICTURE */}

<SessionSection id="big-picture" label="Big Picture">

## Same model, same weights -- the only difference is a scratchpad

Thinking mode does not use a different model or a smarter architecture. It gives the model a hidden scratchpad -- a space to generate reasoning tokens for itself, before producing the visible answer. The transformer runs exactly the same way. The only difference is that some output tokens are internal working-out, and only the final tokens are shown to you.

## The scratchpad works because each token becomes context for the next

Remember from Session 1: every token the model predicts gets added to the context window and influences the next prediction. The scratchpad exploits this directly. When the model writes "wait -- this approach fails if the input is empty... let me try differently..." that correction is now in the context. The model predicts the final answer starting from a context that includes a full worked solution -- not a cold start. It is the same mechanism as normal prediction, used as rough work.

### Thinking budget controls how long the scratchpad can be

You set the thinking budget as a token limit -- the maximum number of scratchpad tokens the model can use before it must start answering. A small budget (1,000 tokens) gives the model a short notepad. A large budget (10,000+ tokens) gives room to try multiple approaches, catch multiple mistakes, and reason through genuinely hard problems. The model stops the scratchpad early if it reaches a confident answer -- the budget is a ceiling, not a fixed cost.

### Does the model actually reason? The honest answer

Thinking mode produces better answers on hard problems -- that is empirically true. But the model is not reasoning the way a human does. It has no internal goal state, no working memory separate from the context window, and no ability to truly backtrack -- it can only write tokens that describe a revision. What is happening is closer to: the model has seen millions of examples of humans writing rough work, and it reproduces that pattern. The rough-work pattern happens to produce better context for the final answer. Whether that counts as "reasoning" is genuinely debated. What is not debated is that it works -- and costs more.

<SessionSection id="practical-example" label="Practical Example">

## A legal document tool that uses two modes on the same document

A team builds a contract analysis tool. It does two jobs on every uploaded contract: first it classifies the document type (NDA, employment contract, SaaS agreement), then it extracts and summarises key liability clauses. Classification is pattern recognition -- the model sees the structure and headings and knows immediately. Fast mode handles it correctly in under 2 seconds. Clause extraction requires reading nested conditions, spotting cross-references, and reasoning about what is implied but not stated. Medium thinking (5,000 token budget) improves accuracy significantly on this task. The team runs two separate API calls on the same document -- one with no thinking budget, one with medium -- rather than applying the expensive mode to everything.
