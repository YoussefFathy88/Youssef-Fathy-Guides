Agent Memory Types

Understand the four types of memory an AI agent can have and when to use each one

By default, LLMs are stateless -- every API call starts from scratch with no memory of what came before. If you want an agent to remember anything, you have to design that memory system yourself. This session maps the four memory types, what each stores, where it lives, and which problem it solves.

Semantic memory: facts and knowledge the agent can look up

Episodic memory vs semantic memory -- what each one actually stores

Toggle between the two sides to compare.

Episodic memory -- records of events

  • 'On 3 March, user reported a login error on their mobile app'
  • 'Agent escalated the ticket to tier-2 support'
  • 'Issue was resolved by resetting the OAuth token'
  • Always tied to a specific time, user, and outcome
VS

Semantic memory -- statements of fact

  • 'OAuth tokens in this system expire after 24 hours'
  • 'Tier-2 support handles all authentication-related issues'
  • 'The mobile app login flow uses Auth0 as the identity provider'
  • Not tied to any event -- true regardless of when you ask

What we covered

In-context memoryEverything currently in the context window -- fast and always available, but temporary and limited by context window size
Episodic memoryA stored log of past interactions saved to an external database and retrieved at the start of future sessions
Semantic memoryA store of facts and knowledge retrieved on demand when the agent needs specific information -- RAG is the main implementation
Procedural memoryRules and instructions loaded at agent startup that define how the agent behaves throughout the session
StatelessThe default behaviour of an LLM -- no memory of previous API calls, every request processed independently from scratch
