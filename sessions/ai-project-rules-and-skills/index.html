What are project rules

1 / 3

Every session starts cold — without rules, the AI has no memory of your standards.

No rules — generic output

function get_user_data(id) {
  return db.query('SELECT * FROM users...')
}

With rules — matches project style

By default the AI writes its own naming, its own patterns, its own file structure — inconsistent across sessions and hard to maintain.

Writing rules that actually work

1 / 3

A good rule has three parts: context, instruction, and an example.

Vague (bad)

“Use clean code.”

Building your skill library

1 / 3

Five skills worth having in any project, regardless of stack.

Create a new service / module

"new service for X"

Add a new API endpoint

"add endpoint for X"

Write a database migration

"migration for this schema change"

Create a test for a function

"test for X"

Review a diff for issues

"review this diff"
