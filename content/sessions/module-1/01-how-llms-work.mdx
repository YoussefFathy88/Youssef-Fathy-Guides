## Understand what actually happens when you call an LLM



You have called LLM APIs, seen the output stream back token by token, and noticed that the same prompt gives different answers each time. This session explains the full mechanical picture from how the model was built, to how it generates each word, to why it behaves the way it does.

## Two distinct phases: training and inference



Every LLM goes through two completely separate phases. Training happens once and is enormously expensive. It produces the model weights. Inference happens every time you send a prompt. It is fast and uses those frozen weights to generate a response. As a developer, you only ever interact with the inference phase.

## Inside the network forward pass



The **forward pass** is the part of every token loop where the model turns your prompt into **logits** — raw scores for every token in its vocabulary. The deep stack inside that pass always runs the same three stages: **tokenization**, **embedding**, and the **transformer**. Each of these is a full topic in its own right — the next sessions cover them in depth. After the stack, **softmax** turns logits into probabilities and **sampling** draws the next token; that decode step is where randomness enters, while the path through logits is deterministic for fixed weights. For now, the goal is to hold the full pipeline in your head so everything that follows has a place to land.

## Inference: one token at a time, every time



When you send a prompt, the model runs a forward pass through all its layers and emits **logits** — one raw score per vocabulary token. **Softmax** turns those logits into a probability distribution; it does not produce a finished sentence by itself. One token is **sampled** from that distribution, appended to the context, and the whole process repeats until the response is complete.

### From logits to probabilities



The model does not output probabilities directly. It outputs raw scores called logits — one per token in its vocabulary. These scores are then passed through a softmax function to produce the probability distribution you sample from.

### Controlling randomness with Temperature

Because the model gives us a probability distribution rather than a single fixed token, we can control how it samples from that distribution using a parameter called **Temperature**. A temperature of 0 always picks the most likely token (deterministic), while a higher temperature flattens the distribution, giving lower-probability tokens a greater chance to be selected. This is the primary lever you have for controlling the trade-off between predictable accuracy and creative variance.

## What we covered



<RecapTable

  rows={[

    { term: "Training", definition: "One-time process of adjusting model weights by predicting next tokens across trillions of examples." },

    { term: "Weights", definition: "Frozen numerical parameters that encode the model's knowledge after training finishes." },

    { term: "Inference", definition: "Serving the model at runtime: repeat a full token step (network forward pass to logits, then softmax and sampling, then append) until the response is complete." },

    { term: "Forward pass", definition: "The deterministic stack from raw text through tokenization, embedding, and transformer layers to logits — one raw score per vocabulary token, before softmax." },

    { term: "Tokenization", definition: "Splitting raw text into subword tokens and mapping each to an integer ID — the very first stage of every forward pass." },

    { term: "Embedding", definition: "Converting token IDs into dense vectors so the transformer can do mathematical operations on meaning." },

    { term: "Transformer", definition: "The N-layer attention-based network that processes the embedded vectors and builds a contextual representation of the full prompt." },

    { term: "Logits", definition: "Raw, unnormalized scores the model assigns to every vocabulary token before softmax is applied. Higher logit = higher probability after normalization." },

    { term: "Temperature", definition: "Parameter that controls how flat or spiky the token probability distribution is at sampling time." },

  ]}
