## Understand what actually happens when you call an LLM

You have called LLM APIs, seen the output stream back token by token, and noticed that the same prompt gives different answers each time. This session explains the full mechanical picture from how the model was built, to how it generates each word, to why it behaves the way it does.

</SessionSection>

## Two distinct phases: training and inference

Every LLM goes through two completely separate phases. Training happens once and is enormously expensive. It produces the model weights. Inference happens every time you send a prompt. It is fast and uses those frozen weights to generate a response. As a developer, you only ever interact with the inference phase.

## Training: compressing the internet into weights

During training, the model reads enormous amounts of text and learns one task: predict the next token. It does this billions of times, adjusting its internal weights each time it gets a prediction wrong. By the end, those weights have compressed a statistical representation of language, and a surprising amount of world knowledge, into a single file.

### Inference: one token at a time, every time

When you send a prompt, the model runs a forward pass through all its layers and produces a probability score for every token in its vocabulary. It does not produce a sentence. It produces a distribution over what token should come next. One token is sampled from that distribution, appended to the context, and the whole process repeats until the response is complete.

### The output is a probability distribution, not a lookup

This is the most important thing to internalize. The model does not retrieve answers from a database. For every token position, it produces a ranked probability distribution across its possible next tokens. The token actually emitted depends on that distribution and on the sampling strategy, which is why the same prompt can yield different outputs.

## Why your API responses are non-deterministic by default

You are building a code review tool. You send the same prompt twice and get different suggestions each time. This is not a bug. It is temperature in action. The model's distribution for code tokens is not perfectly peaked, so there are several plausible next tokens at each step. With temperature at 1.0, the model samples from that spread. Set temperature to 0 and the output becomes deterministic, which is exactly what you want for a code review tool but not for a brainstorming assistant.
