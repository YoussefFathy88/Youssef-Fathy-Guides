## Understand what actually happens when you call an LLM



You have called LLM APIs, seen the output stream back token by token, and noticed that the same prompt gives different answers each time. This session explains the full mechanical picture from how the model was built, to how it generates each word, to why it behaves the way it does.

## What we covered



<RecapTable

  rows={[

    { term: "Training", definition: "One-time process of adjusting model weights by predicting next tokens across trillions of examples." },

    { term: "Weights", definition: "Frozen numerical parameters that encode the model's knowledge after training finishes." },

    { term: "Inference", definition: "Serving the model at runtime: repeat a full token step (network forward pass to logits, then softmax and sampling, then append) until the response is complete." },

    { term: "Forward pass", definition: "The deterministic stack from raw text through tokenization, embedding, and transformer layers to logits — one raw score per vocabulary token, before softmax." },

    { term: "Tokenization", definition: "Splitting raw text into subword tokens and mapping each to an integer ID — the very first stage of every forward pass." },

    { term: "Embedding", definition: "Converting token IDs into dense vectors so the transformer can do mathematical operations on meaning." },

    { term: "Transformer", definition: "The N-layer attention-based network that processes the embedded vectors and builds a contextual representation of the full prompt." },

    { term: "Logits", definition: "Raw, unnormalized scores the model assigns to every vocabulary token before softmax is applied. Higher logit = higher probability after normalization." },

    { term: "Temperature", definition: "Parameter that controls how flat or spiky the token probability distribution is at sampling time." },

  ]}

/>
