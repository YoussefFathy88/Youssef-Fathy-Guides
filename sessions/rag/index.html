RAG

Understand the full RAG pipeline from raw data to grounded LLM answer -- and where memory fits in

Last session introduced semantic memory as a concept. RAG is how you actually build it. This session walks the complete pipeline: loading your data, splitting it into chunks, embedding those chunks into a vector database, and retrieving the right ones at query time so the LLM can answer with grounded, up-to-date information instead of relying only on what it learned during training.

What we covered

RAG (Retrieval-Augmented Generation)A pattern that combines a frozen LLM with an external document store, retrieving relevant chunks at query time to ground the model's answers
ChunkingSplitting documents into overlapping fixed-size segments (typically 200-500 tokens) so each segment can be independently embedded and retrieved
Non-parametric memoryKnowledge stored outside the model's weights in an external database -- can be updated without retraining the model
Vector databaseA database optimised for storing and searching high-dimensional vectors by similarity -- used to index and retrieve document chunks
Top-k retrievalFetching the k most similar chunks to the query vector (typically k=3-5) to inject into the LLM's context window
