<SessionSection id="goal" label="Goal">

Most developers use LLMs without knowing what actually happened before the model reached them — and that blind spot causes real mistakes: fine-tuning when pre-training data is the problem, choosing the wrong alignment technique, or misreading benchmark scores. This session walks you through every stage of the modern training pipeline, from raw data collection to a quantized deployed model, and shows you exactly what the model can and cannot do after each one. After watching, you'll be able to look at any LLM and describe precisely which training stages shaped its behavior.

</SessionSection>

<SessionSection id="big-picture" label="Big Picture">

Training an LLM is not one thing. It is a six-stage factory line — each stage takes the output of the previous one and transforms it. Raw text becomes clean tokens. Clean tokens become a base model. A base model becomes an instruct model. An instruct model becomes an aligned model. An aligned model gets stress-tested. Then it gets compressed and shipped. Miss any stage or do it badly, and the entire downstream chain degrades.

### Stage 1 — Data Engineering: Building the World the Model Will Learn From

Before a single weight is updated, you need to build the dataset. Modern LLMs train on trillions of tokens — Llama 3, for example, trained on over 15 trillion tokens. That data comes from web crawls (Common Crawl being the dominant source), books, code repositories, and curated domain databases. But raw web data is unusable directly. It goes through three cleaning passes: **deduplication** (removing repeated text so the model doesn't memorize boilerplate), **quality filtering** (removing gibberish, spam, and low-signal pages), and **PII scrubbing** (removing personally identifiable information). What's left is then **tokenized** — split into subword chunks using BPE (Byte-Pair Encoding), turning human text into sequences of integer IDs the model can process. Llama 3 uses a vocabulary of 128,000 tokens, meaning roughly 100 tokens cover every 75 words of English. The quality of this pipeline has a bigger impact on the final model than almost any other decision.

### Stage 2 — Pre-Training: Learning Language and the World

Pre-training is the most computationally expensive step — and the source of almost everything the model knows. The setup is deceptively simple: feed the model a token sequence, have it predict the next token, calculate the error (cross-entropy loss), and use backpropagation to adjust billions of weights. Do that trillions of times across the entire dataset. No human labels are needed — the text itself provides the supervision. Over time, the weights encode grammar, facts, reasoning chains, and even programming logic — not by memorizing text, but by compressing statistical patterns into a 175-billion-parameter (GPT-3) or larger network. The simulator below shows what that loss-falling curve actually looks like, and how learning rate shapes convergence.

### Stage 3 — Supervised Fine-Tuning: Teaching the Model to Follow Instructions

SFT takes the pretrained base model and shows it thousands of curated **Prompt → Response** pairs written by humans. A pair looks like: `[User: Summarize this article] → [Assistant: This article discusses…]`. The training objective is the same next-token prediction — but now applied only to the response tokens, not the prompt. The model learns the *format* of being an assistant. It does not learn new facts; it learns that when it sees a prompt, the right output pattern is a direct, helpful answer — not a text continuation. Research (the LIMA paper, 2023) showed that even ~1,000 high-quality examples can fundamentally reshape output behavior. After SFT, give it "What is the capital of France?" and it now returns "The capital of France is Paris." — because that's the pattern in the instruction examples.

The model now behaves like an assistant. But it still doesn't know which *style* of answer people actually prefer — safe vs. unsafe, verbose vs. concise, honest vs. sycophantic. That's what alignment addresses.

### Stage 4 — Alignment: RLHF and DPO

A helpful instruct model can still produce harmful, biased, or dishonest responses — because SFT only taught it format, not values. Alignment training injects human preferences directly into the weights. **RLHF** (Reinforcement Learning from Human Feedback) works in three steps: human raters compare pairs of model responses and pick the better one → those comparisons train a **Reward Model** (a separate network that scores any response) → then RL (specifically PPO) fine-tunes the LLM to maximize the reward model's score while a KL-divergence penalty keeps it from drifting too far from its SFT starting point. **DPO** (Direct Preference Optimization) achieves the same result without the reward model or RL loop — it optimizes the LLM directly on preference pairs `(chosen, rejected)` in a single training step. DPO is now the production standard — Llama 3.1 and Llama 4 both use it because it's more stable and cheaper than PPO.

### Stage 5 — Evaluation and Red Teaming: Stress-Testing Before Release

Before any model ships, it goes through two complementary checks. **Benchmarks** test raw capability on standardized exams: MMLU (57-subject academic knowledge test), HumanEval (code generation), GSM8K (grade-school math), and others give labs a comparable score across model versions. These test what the model *can* do. **Red Teaming** tests what the model *will* do when pushed. Security researchers and adversarial testers craft prompts designed to bypass alignment — asking for dangerous instructions through fictional framings, jailbreaks, or edge cases. If the model fails, alignment training is iterated. Both checks gate whether the model proceeds to deployment.

### Stage 6 — Deployment and Optimization: Making the Model Runnable

A model like Llama 3.1 405B uses 405 billion parameters, each stored as a 16-bit floating point number — roughly 810 GB just for the weights. That's not feasible on consumer hardware or at low inference cost. Two techniques shrink it. **Quantization** reduces the numerical precision of each weight — from FP16 (16-bit) down to INT8 or INT4 — trading a tiny drop in accuracy for a 2–4× reduction in memory and a significant speedup. INT4-quantized models typically score within 1–2% of the original on standard benchmarks. **Context Extension** uses continued training on long-document data plus positional embedding scaling (RoPE scaling) to push the model's usable context window from a base of 8K or 32K tokens up to 128K, 200K, or even 1M+ tokens.
