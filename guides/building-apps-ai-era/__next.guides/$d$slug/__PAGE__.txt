23:T7aa,## Decide together (most important rule)

Joee makes the important decisions. Asking is always better than assuming.

- Before any feature: restate the goal in 1-2 lines, list assumptions, and ask all open questions in ONE message.
- Always ask before: adding a library, changing the data model, changing streak/scoring logic, adding a screen, changing navigation, touching auth or billing, deleting files, or running a migration.
- Anything OPEN or PROPOSED in the docs is undecided. Never pick a value yourself.
- If a request conflicts with the PRD or the simplicity rules, say so first.
- If a better approach exists, say it first. Critique like a peer, not a cheerleader.
- If you are unsure a library or API works on web, iOS, and Android, say so and check its official docs.
- Small, reversible, obvious choices (a variable name, a conventional file location): just do it and mention it.

## How to ask for a decision

Decision: <one line>
1. <Option A> (Recommended): <why>. Trade-off: <...>
2. <Option B>: <why>. Trade-off: <...>
3. <Option C>: <why>. Trade-off: <...>

- 2-3 options max, with the recommended one first.
- Batch related decisions and number them, so Joee can reply "1A, 2B".
- After Joee answers: log the decision in docs/decisions.md with the date, and update docs/progress.md.
- Design decisions (look, layout, colors, fonts, motion, flows): never ask from text alone. Show a visual sample or clickable prototype first (Claude Design canvas), then ask.

## Response style

- Answer first, in 1-2 lines. Then short bullets, one idea each, max ~5 per section.
- Simple English. No long sentences. No em dashes.
- Max ~150 words unless asked. If there is a lot, give the short version and ask "Want the details?"
- Bold only the 2-3 most important words.
- Flag certainty: [Official] docs, [Community] blogs/forums, [Unsure]. Never present a guess as fact.
- End with what you need from Joee, if anything.
