<SessionSection id="goal" label="Goal">

## Understand the four types of memory an AI agent can have and when to use each one

By default, LLMs are stateless -- every API call starts from scratch with no memory of what came before. If you want an agent to remember anything, you have to design that memory system yourself. This session maps the four memory types, what each stores, where it lives, and which problem it solves.

</SessionSection>


{/* SECTION 2 - BIG PICTURE */}

<SessionSection id="big-picture" label="Big Picture">

## Memory is what turns a stateless model into an agent that learns over time

Without a memory system, your agent forgets everything the moment a session ends. The four memory types solve different parts of that problem: active working context, past experiences, factual knowledge, and learned procedures. Most real agents combine two or more of them.

## In-context memory: the agent's active working space

In-context memory is everything currently inside the context window: the system prompt, the conversation so far, retrieved documents, and the current user message. It needs no external infrastructure and is instantly available. Its limit is the context window itself, so old content gets truncated and disappears unless you save it somewhere else.

### Episodic memory: a searchable log of past sessions

Episodic memory stores records of specific past interactions: what the user asked, what the agent did, and what happened next. Those records are saved to an external store and the most relevant ones are pulled back into context in later sessions. It answers the question, "what happened before?"

### Semantic memory: facts and knowledge the agent can look up

Semantic memory stores factual knowledge that is independent of any single interaction: product docs, company policies, domain knowledge, user preferences, or bug lists. The agent queries it when it needs a fact, not a story about a past event. RAG is the most common implementation, and the next session opens up exactly how that retrieval flow works.

### Procedural memory: the instructions that shape how the agent behaves

Procedural memory stores rules, workflows, and decision logic: how to handle a refund, which tool to call, how to format an answer, and when to escalate. In practice it lives in the system prompt, tool definitions, or startup configuration. Unlike episodic and semantic memory, it is usually loaded once at the beginning and shapes every decision that follows.

<SessionSection id="practical-example" label="Practical Example">

## A customer support agent using all four memory types together

A SaaS company builds a support agent for enterprise customers. In-context memory holds the live conversation while episodic memory retrieves the most relevant past tickets so the agent already knows what happened before. Semantic memory supplies product facts from documentation, and procedural memory defines when to resolve the issue directly versus escalate to a human.
