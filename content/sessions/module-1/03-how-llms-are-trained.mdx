<SessionSection id="goal" label="Goal">

Most developers use LLMs without knowing what actually happened before the model reached them — and that blind spot causes real mistakes: fine-tuning when pre-training data is the problem, choosing the wrong alignment technique, or misreading benchmark scores. This session walks you through every stage of the modern training pipeline, from raw data collection to a quantized deployed model, and shows you exactly what the model can and cannot do after each one. After watching, you'll be able to look at any LLM and describe precisely which training stages shaped its behavior.

</SessionSection>

## What we covered

<RecapTable rows={[
  {
    term: "Pre-training",
    definition: "The first phase where a model learns to predict the next token on trillions of tokens of raw text, acquiring language and world knowledge through self-supervised learning.",
  },
  {
    term: "Supervised Fine-Tuning (SFT)",
    definition: "Post-training step using curated prompt-response pairs to teach the model to follow instructions — shapes behavior without changing the underlying knowledge.",
  },
  {
    term: "RLHF",
    definition: "Reinforcement Learning from Human Feedback — human preference rankings train a Reward Model, which guides RL fine-tuning to align the LLM with what people actually prefer.",
  },
  {
    term: "DPO",
    definition: "Direct Preference Optimization — the modern production alternative to RLHF that fine-tunes the LLM directly on preference pairs with no reward model or RL loop.",
  },
  {
    term: "Quantization",
    definition: "Reducing the numerical precision of model weights (e.g. FP16 → INT4) to shrink memory footprint and speed up inference, typically with less than 2% accuracy loss.",
  },
]} />
